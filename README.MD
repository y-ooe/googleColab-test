## 1. 用語集

読み飛ばさず、分からない語が出たらここに戻ってください。

### 学習まわり

| 用語 | 意味 |
|---|---|
| **モデル** | 「入力を入れると出力が出る計算式のかたまり」。中身は大量の数値（＝**重み**）。 |
| **重み / ウェイト** | モデルの中身の数値そのもの。学習とは、この数値を少しずつ調整する作業。 |
| **学習（トレーニング）** | 「この入力にはこの出力が正しい」という例をたくさん見せて、重みを正解に近づけること。 |
| **データセット** | 学習に使う例の集合。ここでは「音声ファイル」と「その音声の文字起こし」のペア一式。 |
| **ベースモデル（底模）** | 大量の他人の音声で事前に学習済みの、出発点となるモデル。GPT-SoVITS が最初から持っている。 |
| **ファインチューニング（微調整）** | ゼロから作らず、ベースモデルの重みを自分のデータで少しだけ上書きすること。**今回やるのはこれ。** 数十分の音声で足りるのはベースモデルが下地を作っているから。 |
| **エポック (epoch)** | データセット全体を頭から最後まで1回通しきること。8エポック＝全データを8周。 |
| **ステップ (step)** | 重みを1回更新する単位。1エポック中に何十〜何百ステップも走る。`1エポックのステップ数 ≒ データ件数 ÷ バッチサイズ`。 |
| **バッチサイズ (batch_size)** | 1ステップで同時に処理する音声の個数。大きいほど速いがメモリを食う。 |
| **学習率 (learning rate)** | 1回の更新で重みをどれだけ動かすか。大きすぎると壊れ、小さすぎると進まない。WebUI では基本いじらない。 |
| **過学習（オーバーフィッティング）** | 学習しすぎて、データを「覚えて」しまい応用が効かなくなる状態。声では、学習に使った文の言い回しに引きずられる、ノイズまで再現する、未知の文で崩れる、といった形で出る。**「学習は多いほど良い」わけではない最大の理由。** |
| **チェックポイント (ckpt)** | 学習途中の重みを保存したファイル。途中の複数エポックを保存しておき、**聴き比べて一番良いものを選ぶ**のが正しい使い方。 |
| **推論 (inference)** | 学習済みモデルを使って実際に出力を得ること。ここでは「テキストを入れて音声を出す」こと。学習とは別の工程。 |
| **ゼロショット** | 学習を一切せず、参照音声だけでその声を真似させること。すでに成功しているやつ。似ているが精度は学習版に劣る。 |

### 音声・このソフト固有

| 用語 | 意味 |
|---|---|
| **TTS** | Text To Speech。文字→音声。 |
| **ASR** | Automatic Speech Recognition。音声→文字（文字起こし）。今回は録音した音声の台本を自動生成するために使う。 |
| **アノテーション / ラベル付け** | 「この音声ファイルの中身はこの文です」という対応表を作ること。その対応表が `.list` ファイル。 |
| **参照音声 (reference audio)** | 推論時に「この声色・この喋り方で」と見本として渡す3〜10秒の音声。**学習後も毎回必要。** モデルが声の情報を全部持っているわけではなく、参照音声で最終的な声色が決まる。 |
| **参照テキスト** | 参照音声に何と言っているかを書いた文字列。一字一句合っている必要がある。 |
| **音素 (phoneme)** | 発音の最小単位（k, a, t, a …）。日本語テキストは内部で音素に変換されてから扱われる。 |
| **GPTモデル (s1)** | テキスト → 「どう喋るか」の中間表現を作る側。**抑揚・間・リズム**を担当。保存先 `GPT_weights_v2Pro/`。 |
| **SoVITSモデル (s2)** | 中間表現 + 参照音声 → 実際の波形を作る側。**声質・音色**を担当。保存先 `SoVITS_weights_v2Pro/`。 |
| **セマンティックトークン** | GPT側が出し、SoVITS側が受け取る中間表現。前処理 1Ac で作る。 |
| **SSL特徴 / HuBERT** | 音声から「発音内容の特徴」を取り出したデータ。前処理 1Ab で作る。 |
| **sv（話者埋め込み）** | 声の個人性を数値化したもの。**v2Pro で追加された仕組みで、話者の類似度が上がる理由がこれ**。前処理 1Ab が v2Pro のとき一緒に作る。 |

### ハード・実行環境

| 用語 | 意味 |
|---|---|
| **GPU** | 学習・推論を高速に行う計算機部品。Colab の T4 がこれ。 |
| **VRAM** | GPU 専用のメモリ。T4 は約15GB。**足りないと `CUDA out of memory` で落ちる。** バッチサイズが直接効く。 |
| **RAM** | CPU側のメモリ。Colab 無料枠は約12GBで、ここが溢れるとセッションごとクラッシュする。前処理を同時実行しない理由。 |
| **OOM** | Out Of Memory。メモリ不足で落ちること。 |
| **fp16 / 半精度** | 数値を軽い形式で扱い、速度とメモリを稼ぐ設定。T4 では自動で有効になる。 |
| **Gradio** | この WebUI を作っているライブラリ。`*.gradio.live` の公開URLはこれが発行している。 |

## 2. 全体の流れ

```
[録音]  30分〜1時間の自分の声（1本の長い音声でよい）
   ↓  0b 音声分割        長い音声は学習に使えない。3〜10秒の断片に切る
[断片 wav が数百個]
   ↓  0c ASR             断片1つ1つの文字起こしを自動生成（台本作りの下書き）
[.list ファイル]          「ファイル名|話者|JA|テキスト」の一覧
   ↓  0d 校正            ASRの誤りを手で直す ← 品質を最も左右する
[正しい .list]
   ↓  1A 前処理          音声とテキストを、学習プログラムが読める数値に変換
[logs/実験名/ に中間ファイル]
   ↓  1B 学習            ベースモデルを自分のデータで微調整
[SoVITS_weights_v2Pro/ と GPT_weights_v2Pro/ にモデル]
   ↓  1C 推論            自分のモデル＋参照音声＋テキスト → 音声
[完成]
   ↓  Driveへ退避        Colabが切れると /content は消える
```

各工程が必要な理由:

| 工程 | なぜ必要か |
|---|---|
| 0b 分割 | 学習は短い断片単位で行う。長い音声のままでは VRAM に載らず、また「どの区間がどの文か」が決まらない。 |
| 0c ASR | 数百件の文字起こしを手打ちするのは非現実的。機械に下書きさせる。 |
| 0d 校正 | 学習は「音声＝このテキスト」を無条件に正しいと信じて発音を覚える。誤りは発音の壊れとして直接モデルに焼き付く。 |
| 1A 前処理 | 学習プログラムは wav とテキストを直接読まない。音素列・BERT特徴・SSL特徴・セマンティックトークンへ事前変換しておく（毎ステップ変換すると遅いため）。 |
| 1B 学習 | ここで初めて重みが自分の声に寄る。SoVITS（声質）と GPT（抑揚）は別々に学習する。 |
| 1C 推論 | 学習結果を確認する。良し悪しの判断はここで耳で行う。 |

**所要時間の目安（要確認 / T4・30分素材の場合）**: 0b 数分 / 0c 10〜20分（初回モデルDL含む） / 0d 1〜3時間（人手） / 1A 10〜30分 / 1B SoVITS 30〜60分・GPT 30〜60分。**0d が一番長い**と思っておくのが安全です。

## 3. 事前準備：録音とファイルの置き場所

### 録音
- **48kHz / 16bit以上 / 無圧縮（wav）**。mp3 など圧縮済みの音源は劣化がモデルに乗る。
- 静かな部屋、マイクとの距離を一定に。エアコン・PCファンの音も学習対象になる。
- 台本は **ITAコーパス**（無料公開の日本語読み上げ台本）が定番。音のバランスが設計されていて少量でも効率が良い。
- **チャットゲーム用途なら感情のバリエーションを入れる。** 平静な朗読だけで学習すると、平静な喋り方しか出にくい（要確認: どの程度効くかはデータ依存）。
- 1本の長ファイルでよい。分割は 0b がやる。

### 置き場所
Colab が切れると `/content` は消えます。**素材は Drive に置き、作業は `/content` で行う**のが基本です。

```
/content/drive/MyDrive/gpt_sovits/raw/     ← 録音した wav をここに（Driveなので消えない）
/content/GPT-SoVITS/output/slicer_opt/     ← 0b の出力（Colab内。速いが消える）
/content/GPT-SoVITS/output/asr_opt/        ← 0c の出力 .list
/content/GPT-SoVITS/logs/<実験名>/          ← 1A の中間ファイル
/content/GPT-SoVITS/SoVITS_weights_v2Pro/  ← 学習結果（声質）
/content/GPT-SoVITS/GPT_weights_v2Pro/     ← 学習結果（抑揚）
```

> 中間ファイル（`logs/`）を Drive 上に置くと I/O が遅く学習が遅延します。Colab 内で処理し、**結果だけ Drive にコピー**してください。

### 4-1. タブ「0-前処理データセット取得ツール」

#### 0a-UVR5 ボーカル分離＆リバーブ・ディレイ除去

**自分で静かに録音するなら使いません。読み飛ばして構いません。**

- 用途: BGM付き音源からボーカルだけを抜く、残響を取る。
- 今回のセットアップでは `install.sh` に `--download-uvr5` を付けていないため、**UVR5用モデルが未ダウンロードで動かない可能性が高い**（要確認）。使いたい場合はモデルの追加取得が必要。
- 分離処理は必ず音質を削ります。原則「最初からクリーンに録る」が正解。

#### 0b-音声分割ツール

長い録音を学習可能な断片に切ります。

| 入力欄 | 入れるもの |
|---|---|
| 音声自動分割の入力パス | `/content/drive/MyDrive/gpt_sovits/raw`（フォルダでもファイルでも可） |
| 分割後のサブオーディオの出力ルートディレクトリ | `output/slicer_opt`（既定のままでよい） |

パラメータ（既定値のままで概ね動きます）:

| 項目 | 既定 | 意味 | いじる場面 |
|---|---|---|---|
| threshold | -34 | この音量(dB)より小さい部分を「無音候補」とみなし、そこで切る | 息継ぎで切れすぎる → 下げる(-40)。長い断片ばかり → 上げる(-30) |
| min_length | 4000 | 1断片の最短の長さ(ミリ秒)。短いと後ろと連結される | 断片が短すぎるとき上げる |
| min_interval | 300 | これ以上続く無音でないと切らない(ms) | 細切れになるとき上げる |
| hop_size | 10 | 音量カーブの計算間隔。小さいほど細かいが重い | 基本触らない |
| max_sil_kept | 500 | 切った後に前後へ残す無音の長さ(ms) | 基本触らない |
| max | 0.9 | 音量正規化の最大値 | 基本触らない |
| alpha_mix | 0.25 | 正規化した音をどれだけ混ぜるか | 基本触らない |
| 切り分けに使うプロセス数 | 4 | 並列数 | Colabでクラッシュするなら下げる |

**手順**: パスを入力 → 「有効化音声分割」 → 出力情報に完了が出るまで待つ。

**成功の確認**（Colabの別セルで実行）:
```python
!ls /content/GPT-SoVITS/output/slicer_opt | head
!ls /content/GPT-SoVITS/output/slicer_opt | wc -l
```
- **30分の素材なら概ね 300〜600 ファイル**（要確認: 喋る密度による）。
- 極端に少ない（数十）＝ 1断片が長すぎる。極端に多い（数千）＝ 細切れ。どちらも threshold / min_length を調整してやり直す。
- **理想は1件3〜10秒。** 10秒を大きく超える断片が多いと、学習時のメモリと品質の両方に効きます。

> なぜ長さを揃えるか: 学習は断片単位で行われ、長い断片ほど VRAM を食い、また「参照音声3〜10秒」という推論側の前提とも揃えておいた方が結果が安定するためです。

#### 0bb-音声ノイズ除去

**現行の main では、この項目は画面に表示されません**（「不安定でモデル品質を劣化させる可能性がある」として開発側が非表示にしています）。表示されている版なら使えますが、**使わないことを推奨します**（要確認: 版によって表示/非表示が変わる）。

ノイズが乗ってしまった場合は、このツールに頼らず録り直すか、外部ツール（Audacity のノイズ除去など）で処理してから 0b に戻る方が安全です。

#### 0c-音声認識ツール（ASR）

断片ごとの文字起こしを自動生成します。

| 入力欄 | 入れるもの |
|---|---|
| 入力フォルダのパス | 0b の出力。**0b を実行していれば自動で入っています**（例: `output/slicer_opt`） |
| 出力フォルダのパス | `output/asr_opt`（既定のまま） |
| ASR モデル | **Faster Whisper（多言語）** を選ぶ |
| ASRモデルサイズ | `large-v3` |
| ASR 言語設定 | **`ja`** ← 最重要。`auto` にしない |
| データ型の精度 | `float16`（T4なら可。不安なら `float32`） |

> 新しい版では `Fun-ASR-Nano` / `SenseVoice` も選択肢に出ます。どちらも日本語対応ですが、**日本語の精度比較は未確認（要確認）**。迷うなら Faster Whisper。
> 言語を `ja` に固定する理由: `auto` だと断片ごとに言語判定が揺れ、中国語や英語として書き起こされた行が混ざります。その行は後段で発音が壊れます。

**手順**: 設定 → 「有効化音声認識」 → 完了まで待つ（初回はモデルのダウンロードで数分〜十数分）。

**成功の確認**:
```python
!ls /content/GPT-SoVITS/output/asr_opt/
!head -3 /content/GPT-SoVITS/output/asr_opt/*.list
!wc -l /content/GPT-SoVITS/output/asr_opt/*.list
```
`.list` の1行はこの形式です:
```
/content/GPT-SoVITS/output/slicer_opt/xxx_0001.wav|slicer_opt|JA|こんにちは、今日はいい天気ですね。
        音声ファイルパス                        |話者名     |言語|テキスト
```
- 行数が wav の数とだいたい一致していれば成功。
- 言語欄が `JA` 以外（`ZH` など）になっている行があれば、ASR の言語設定が間違っています。

#### 0d-音声テキスト校正・ラベル付けツール

**ここが品質を最も左右します。飛ばさないでください。**

| 入力欄 | 入れるもの |
|---|---|
| ラベル付けファイルのパス（*.list を含む） | `/content/GPT-SoVITS/output/asr_opt/slicer_opt.list` のような**フルパス**。0c 実行後は自動で入ります |

**手順**:
1. 「有効化音声アノテーション用WebUI」を押す。
2. **Colab では公開URLが出ません。** 付録A のポート転送セルを実行し、**9871** のURLを開く。
3. 1行ずつ再生して、テキストを聴こえた通りに直す。
4. こまめに **Submit / Save（保存）** を押す。押さないと消えます。

**直すべきもの / 消すべき行**:

| 状態 | 対応 | 理由 |
|---|---|---|
| 聞こえと文字が違う | 直す | 誤った発音を学習する |
| 数字・記号・英字（「2023年」「AI」） | 読み方をかなで書く（「にせんにじゅうさんねん」） | 読み方が一意に決まらず、発音が不安定になる |
| 笑い声・咳・言い淀みのみ | 行ごと削除 | 対応するテキストが存在せず、学習の邪魔になる |
| ほぼ無音 | 行ごと削除 | 同上 |
| 2文以上が1断片に入っている | テキストも全部書く（消さない） | 音声とテキストが対応していればよい |
| 極端に長い（15秒超）/ 短い（1秒未満） | 削除するか、0b をやり直す | メモリ・品質の両面で不利 |

> 全部直す時間がない場合でも、**明らかな誤字と記号・数字だけは直す**と効果が大きいです（要確認: 定量的な検証はしていません）。

### 4-2. タブ「1-GPT-SoVITS-TTS」共通ヘッダ

タブを開くと上部に3つあります。**1A・1B・1C すべてに効くので最初に設定します。**

| 項目 | 設定 |
|---|---|
| ***実験/モデル名** | **半角英数字とアンダースコアのみ**。例 `myvoice01`。日本語・空白は避ける |
| グラフィックカード情報 | 表示専用。`0 Tesla T4` のように出ていればOK |
| 学習済みモデルのバージョン | **v2Pro**（この Colab では既定で v2Pro） |

> 実験名の役割: 中間ファイルは `logs/<実験名>/`、学習結果は `SoVITS_weights_v2Pro/<実験名>_e8_s560.pth` のように、すべてこの名前で管理されます。**途中で変えると前処理からやり直しになります。**
> バージョンの役割: ここを切り替えると事前学習モデルのパス・既定のエポック数・出力先フォルダが一斉に切り替わります。**1A を実行した後に変更しないでください**（v2Pro は 1A で専用の sv 特徴を作るため、他バージョンと中間ファイルの構成が違います）。

## 5. パラメータの意味と、上げ下げで起きること

### 5-1. バッチサイズ（batch_size）

**何か**: 1ステップで同時に処理する音声断片の数。

**なぜ存在するか**: 1件ずつ処理すると遅く、更新もブレます。まとめて処理して平均を取ることで、速度と安定性を得ます。

| 上げると | 下げると |
|---|---|
| 学習が速い | 学習が遅い |
| VRAM を多く使う → **OOM で落ちる** | VRAM が少なくて済む |
| 1エポックあたりの更新回数（ステップ数）が減る | 更新回数が増える |
| 更新が安定（平均化される） | 更新がブレる（ノイズが乗る） |

**T4（VRAM 15GB）での既定値は 7 前後**です（WebUI が `VRAM ÷ 2` で自動計算し、スライダー上限はその3倍になります）。

**判断基準**:
- `CUDA out of memory` が出た → **半分にする**（7→4→2）。これ以外の対処は基本不要。
- データが少ないとき（断片 300件程度）、バッチを大きくしすぎると **1エポックが数十ステップしかなくなり、エポック数を増やしても学習が進みません**。
  - 目安: `断片数 ÷ バッチサイズ` が **30〜100** 程度に収まるようにする（要確認: 明確な根拠のある数字ではなく経験的な目安です）。
  - 例: 断片 500件 ÷ バッチ 7 ≒ 71ステップ/エポック → 妥当。
- **バッチサイズを変えたらエポック数も見直す。** バッチを倍にすると1エポックの更新回数は半分になるので、同じエポック数では学習量が実質減ります。

### 5-2. エポック数（total_epoch）

**何か**: データセットを何周するか。**このソフトで一番、結果を左右するパラメータです。**

**少なすぎると**（学習不足）:
- 声が本人に似ない、ベースモデルの声が残る
- 抑揚が平坦・棒読み
- 日本語としては自然だが「別人が読んでいる」感じ

**多すぎると**（過学習）:
- 音がザラつく、電子的なノイズが混じる、こもる
- 学習データにあった言い回し・口調に引きずられる
- 学習データに無い言葉で急に崩れる、途中で暴走する
- 録音環境のノイズや部屋の響きまで再現される

| モデル | 担当 | 既定 | 30分〜1時間での出発点 | 上限 |
|---|---|---|---|---|
| SoVITS (1Ba) | 声質 | 8 | **8〜12** | 25（UI上） |
| GPT (1Bb) | 抑揚・間 | 15 | **12〜20** | 50（UI上） |

> これらの数値は**要確認**です。最適値はデータ量・収録品質・声の特徴で変わります。**1回で当てようとせず、保存頻度を小さくして複数エポックを残し、聴き比べて選ぶ**のが正しいやり方です。

**エポックを「選ぶ」手順**:
1. SoVITS を save_every_epoch=2 で12エポック回す → `_e2`, `_e4`, `_e6`, `_e8`, `_e10`, `_e12` が残る。
2. GPT はとりあえず1本（15エポック）作る。
3. 1C で **GPT を固定したまま SoVITS だけ差し替えて**同じ文を合成し、聴き比べる → 最良の SoVITS が決まる。
4. 次に **SoVITS を固定して GPT を差し替え**、同じことをする。
5. 片方ずつ動かすのは、**同時に変えるとどちらが効いたのか分からなくなる**ためです。

### 5-3. 保存頻度（save_every_epoch）/ 最新のみ保存

- 保存頻度を小さくすると、比較候補が増えます。代わりにディスクを食います（Colab の `/content` は十分な容量があるので、通常は問題になりません）。
- **「最新の重みファイルのみを保存」をオンにすると比較候補が消えます。** 5-2 の手順が使えなくなるのでオフ推奨。
- **「各保存時点で最終的な小さなモデルをweightsフォルダに保存」はオン必須。** これがオフだと、学習ログ用のチェックポイントは残っても、推論に使える軽量モデルが `*_weights_v2Pro/` に出てきません。
- 副次効果として、Colab が切断されても直前の保存まで残ります。

### 5-4. その他の学習パラメータ

| 項目 | 推奨 | 説明 |
|---|---|---|
| テキストモジュールの学習率の重み（1Ba） | **0.4（既定のまま）** | テキストを扱う部分の学習の強さ。下げるとベースモデルの言語能力を保つ方向、上げると自分のデータに寄る方向。触って改善する場面は限定的（要確認） |
| DPO トレーニング（1Bb） | **オフ** | 実験的機能。学習時間とメモリが増える |
| LoRAランク | **v2Pro では表示されません** | v3/v4 用の項目 |
| GPUカード番号 | `0` | Colab は GPU 1枚 |

### 5-5. 推論時のパラメータ（1C の推論WebUI）

学習をやり直さずに調整できる部分です。**まずここを触るべきで、いきなり再学習しないでください。**

| 項目 | 既定 | 上げると | 下げると |
|---|---|---|---|
| top_k | 15 | 候補が増え多様・不安定 | 単調だが安定。**繰り返し・暴走が出るなら 5〜10 に下げる** |
| top_p | 1 | （1が上限） | 安定方向 |
| temperature | 1 | 表情豊か・破綻しやすい | 平坦・安定。**0.6〜0.8 は安定寄りの定番**（要確認） |
| 話速 | 1 | 速い | 遅い |
| 文間のポーズ秒数 | 既定 | 間が長い | 間が詰まる |
| どうやって切るか | 4つの文で埋める | — | 長文が崩れるなら「句読点で分割」に変える |

## 6. 失敗の見分け方

### 6-1. まず切り分ける（これを先にやる）

原因を特定しないまま設定を変えると必ず迷走します。**同じ参照音声・同じテキストで、以下の4通りを合成して比較してください。**

| # | GPT | SoVITS | この結果が意味すること |
|---|---|---|---|
| 1 | ベース | ベース | **ここで既に変** → 参照音声・参照テキスト・推論設定の問題。学習は無関係 |
| 2 | ベース | 自分 | **1より声が似た** → SoVITS の学習は成功している |
| 3 | 自分 | ベース | **1より喋り方が自分らしい** → GPT の学習は成功している |
| 4 | 自分 | 自分 | 最終形 |

この表で「どちらが壊れているか」が分かってから、下の対応表に進みます。

### 6-2. 症状別の対応

#### 声が本人に似ない

| 疑う順 | 確認・対処 |
|---|---|
| 1 | **参照音声**。学習データ内の、クリアで3〜10秒の断片に変える。ここで大きく変わる |
| 2 | **SoVITS のエポック不足**。より後のエポックのモデルに差し替える |
| 3 | **バージョン設定**。`logs/<実験名>/7-sv_cn/` が無ければ v2Pro として前処理できていない。1A からやり直し |
| 4 | **データ量・質**。録音が短い、環境音が多い、マイク距離が不均一 |
| 5 | 複数参照音声を入れて音色を平均化してみる |

#### 音がザラつく / 電子的なノイズ / こもる

| 疑う順 | 確認・対処 |
|---|---|
| 1 | **SoVITS の過学習**。より**前**のエポック（e12 → e6）に差し替える。これで直ることが多い |
| 2 | **学習データのノイズ**。録音にホワイトノイズ・空調音が入っていないか。入っていればモデルはそれも再現する |
| 3 | **参照音声にノイズがある**。別の断片に変える |
| 4 | 0b の正規化で音割れしていないか。`output/slicer_opt` の wav をいくつか聴く |

#### 発音が変 / 読み間違える / 漢字を誤読する

| 疑う順 | 確認・対処 |
|---|---|
| 1 | **0d の書き起こしミス**。その言葉が学習データにどう書かれているか確認する。ここが最頻出原因 |
| 2 | **数字・英字・記号**。学習データ側も推論テキスト側も、かな書きにすると安定する |
| 3 | **ASR の言語設定**。`.list` に `JA` 以外の行が混ざっていないか |
| 4 | 推論側の「推論の言語」が日本語になっているか |

#### 途中で暴走する / 同じ音を繰り返す / 早口になる

| 疑う順 | 確認・対処 |
|---|---|
| 1 | **推論テキストが長い**。「どうやって切るか」を「句読点で分割」に変える |
| 2 | **top_k を下げる**（15→8）、**temperature を下げる**（1→0.7） |
| 3 | **GPT の過学習**。より前のエポックに差し替える |
| 4 | **参照テキストが参照音声と一致していない**。一字一句確認する |

#### 抑揚が棒読み / 感情が出ない

| 疑う順 | 確認・対処 |
|---|---|
| 1 | **参照音声の感情**。出したい感情に近い断片を参照音声にする。**参照音声の影響が一番大きい** |
| 2 | **GPT のエポック不足**。より後のエポックに差し替える |
| 3 | temperature を少し上げる（1.0→1.1前後） |
| 4 | **学習データに感情のバリエーションが無い**。平静な朗読だけなら、追加収録が必要 |

#### 冒頭・末尾が切れる / 無音が混じる

| 疑う順 | 確認・対処 |
|---|---|
| 1 | **参照音声が3〜10秒の範囲外**。範囲内でも、前後に長い無音がある断片は避ける |
| 2 | 0b の `max_sil_kept` が大きすぎて断片に無音が多く含まれている |
| 3 | 推論テキストの末尾に句点があるか |

#### 学習データの口調・言い回しが混ざる

**GPT の過学習**です。前のエポックに戻すか、GPT のエポック数を下げて再学習してください。データ量が少ないほど起きやすくなります。

#### 毎回結果が違う

**仕様です。** GPT 側がランダム性を持つサンプリングで生成しているためです。安定させたいなら temperature / top_k を下げます。完全に固定したい場合は、WebUI ではなく API（`api_v2.py`）の `seed` を指定します。

### 6-3. エラーメッセージ系

| メッセージ | 原因と対処 |
|---|---|
| `CUDA out of memory` | VRAM 不足。**バッチサイズを半分に**。それでも出るなら他のタブの処理が動いていないか確認 |
| セッションがクラッシュしました（Colab） | CPU側 RAM 不足。前処理を同時実行していないか。1Aabc の一括処理をやめて1つずつ実行 |
| `参照音声が3～10秒の範囲外です` | 参照音声を差し替える。**仕様なので回避不可** |
| 1C のモデルリストに自分のモデルが出ない | 「モデルのパスを更新」を押す。それでも出ないなら「weightsフォルダに保存」がオフだった可能性 |
| 1A で `2-name2text.txt` の行数が少ない | `.list` の該当行に変換できない文字がある。セル9の出力にどの行で落ちたか出ている |
| 学習ボタンを押しても何も起きない | 実験名の未設定、`.list` パスの誤り、前工程の未完了。出力情報欄を確認 |

> 判断に困ったら、**まず「6-1 切り分け」に戻ってください。** 症状から直接パラメータをいじるより速く原因に着きます。
